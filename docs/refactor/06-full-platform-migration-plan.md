# ChapterFlow 全平台迁移与补全方案

日期：2026-09-09。产品：ChapterFlow / 文织·网文工坊。

本文件是原 `docs/REFACTOR_MASTER_PLAN.md` 的增量执行方案。依据原始改造附件、当前源码、阶段审计与测试日志制定。它同时作为后续 Goal 的验收边界；旧的“仅执行 Phase 0、1、2、4”描述不能作为今后忽略旧平台功能覆盖的理由。

## 1. 当前判断与范围

当前是“新作品库、新创作首页、新写作台 + 旧工作区共存”的过渡版本，尚不是完整独立的新产品。新 URL、新标题、新侧栏不等于功能迁移完成。

后续分成两层交付，避免混淆：

- **A：完整平台迁移，必做。** 补完原 Phase 1、2、4，接入 Phase 3 开书与导入、Phase 5 设定，并迁移既有助手、连续创作、任务恢复、高级工具、模板、导出备份与设置。普通作者完成全部既有工作不再进入旧 Shell，也不再依赖整页嵌入旧 Workspace。
- **B：原方案中的新增网文能力，排在 A 之后。** 完整 CreativePreset / BookProfile / ChapterBrief、专项质检、前三章体检、真实写作统计、手工发布记录与 CSV 数据复盘。B 有独立数据契约、验收与进度，不能以 A 完成宣称 B 完成。
- **继续排除自动发布。** 参考图“发布（暂时不用实现，手动发布）.png”明确保留手工发布方式；不接自动登录、抓取或自动上传第三方平台。导出、备份等既有能力仍必须覆盖。

“彻底”的含义是作者体验、功能入口、状态恢复、品牌和数据链路闭环，不是全仓库替换 NarraLume 字符串。保留引擎、历史数据兼容标识、包命名与许可证归属，避免因改名破坏存储或导入。

| `/books/:id/knowledge/{intent,characters,world,relations,timeline,foreshadow}` | 唯一故事事实源的不同作者视图                   |

任务与助手抽屉用可恢复状态表示，支持刷新/深链；保存来源作品、章节、选区、任务 ID 和 returnTo。项目外导航不得把 `new/templates/trash` 当作作品 ID。不存在/删除/归档作品与无效参数应分别提示，避免默认回首页掩盖错误。

旧路由映射规则：overview→dashboard；studio→write 并保留 document、outline、focus、run 的语义；bible 按 section 分流大纲或设定；runs→任务中心或指定任务详情；autopilot→连续创作面板及 session；lab→advanced；delivery→publish；shelf→books。无作品旧短链先解析可靠项目上下文，否则让用户选择作品。旧书签兼容不等于继续显示旧页面。

## 4. 分模块实施要求

### W01 稿件安全、路由与恢复（最高优先级）

1. 收尾中断的导航保护，覆盖链接、程序导航、浏览器前进后退、切章、切书、设置、搜索；保存失败时保留编辑现场并可重试。
2. 硬刷新/关页不能依赖卸载时异步网络保存；明确本地恢复机制、恢复提示与草稿过期清理，测试离线和异常退出。
3. 所有采纳/替换/插入/恢复都验证目标作品、文档、基础版本和草稿并发状态；最终写入依靠后端原子条件而非仅前端 GET 检查。冲突时保留双方内容并提供比较/复制/重新生成。
4. AI 请求和采纳保留幂等语义，重复点击、重试及刷新不重复创建章节/版本/任务；同一结果不能以另一动作误重复应用。
5. 覆盖中文输入法组合输入、中文标点、换行、emoji、选区偏移、空章和长章；续写不得改原文，插入不得吃掉原选区或后文。

验收：故障注入和双页面竞争测试都证明没有静默覆盖；最新后退失败用例修复且确实导航至明确不同目的页；恢复版本前有可找回的当前稿。

### W02 工程基础与一致视觉

1. 建立集中路由 builder、旧链解析器、项目上下文和页面权限/存在性边界；避免各组件拼字符串。
2. 补齐 Query Key factory、实体查询 hooks、统一 mutation 失效规则。编辑后作品字数、章节、首页待办、任务候选同步更新，不能各页维护另一套真相。
3. 拆分 ChapterEditor、旧 Studio/Assistant/Autopilot 中可复用业务逻辑，页面只编排；优先按本阶段垂直功能抽离，避免先进行无收益的全仓重写。
4. 统一 Button/Input/Select/Tabs/Drawer/Dialog/Menu/Toast/Empty/Error/Skeleton/Badge/Confirm 等。处理焦点陷阱、Esc、焦点归还、键盘导航、屏幕阅读器标签。
5. 以 `参考 UI 图/` 为视觉依据：统一浅色纸面、蓝色主操作、字体层级、间距、边框、圆角、图标与密度；不只复制颜色。各页面空/加载/失败/长内容状态也要设计。
6. 1440/1024/768/375 四视口验证。桌面写作保持正文中心；窄屏侧栏和工具转抽屉，不挤压正文。错误状态不得仍显示“写作可用”；存储连接与 AI 可用性分别反映真实状态。

验收：普通页面一致、无横向溢出和不可达操作；阶段内不为整理结构随意改 Domain/数据库；必要契约扩展另列说明。

### W03 作品库与三入口开书

- 作品库：完整作品信息编辑、封面上传/裁切/替换/移除、状态、搜索排序、复制范围说明、归档恢复、回收站恢复与彻底删除；列表刷新后结果一致。
- 手工创建：书名、简介、题材、目标读者/男频女频可后补；无模型时同样可创建→大纲→人物→写作→导出。
- AI 创建：一句话→策划任务→三个可比较方案→选择/微调→确认初始化→首页。展示书名、卖点、核心冲突、主线、人物、前三章章纲；不要把旧候选 JSON 当方案 UI。
- 复用 Foundation；现在由 FoundationPlan 契约表达三份完整路线，单独选择才在一个事务内写入意图、指南针和实体，基线变化会拒绝落库；作者确认前不覆盖已有设定，失败可恢复或转手工。
- 导入：先列出现有真实支持格式与能力，再实现文件选择→章节识别→预览调整→可选设定提取→确认导入→打开新作品。解析/手工导入不能依赖 AI；AI 识别失败不阻塞原文保留。
- 覆盖重复导入、编码、空文件、超限、损坏包、章节排序、取消、部分失败与导入记录；导入来源文稿原样可追溯。格式扩展属于明确新增能力，不用 UI 声称未实现格式已支持。

验收：三入口全程新 UI；普通开书不超过 5 个主要决策；重复提交不重复建书；删除→恢复、导出→导入均验证内容与顺序。

### W04 创作首页与作品进度

- 以 overview 契约为基础，唯一突出“继续写作”；没有章节时主操作给出创建第一章，同时保留一个“继续写作”兼容入口，让作者可以直接进入空写作台创建章节；已有未写章纲时给出开始本章。
- 待检查、设定变化、改写建议、任务恢复分别定位到对应章节/对象/面板，显示真实数量和状态。
- 当前章与最近创作时间应来自可靠记录，不能用数组第一项或轮询更新时间假冒最近写作。
- 今日目标/今日字数在 B 阶段增加可信计量：说明净新增还是输入量、AI 采纳是否计入、时区、删除/恢复/跨日去重规则；未接数据前不展示虚构进度。

验收：进入作品后最多两次点击到当前章节；每种待办有真实可完成的下一步，处理后计数收敛。

### W05 原生大纲与章纲

- 左侧全书→卷→章树，右侧可编辑卡片；高级模式保留 arc/scene/beat 等底层层级，不丢已有数据。
- 创建、改名、复制、排序、跨卷移动、删除/恢复策略；有关联正文时明确影响，不能删纲误删稿。
- 章纲：作用、目标、冲突、结果/爽点、钩子、目标字数、人物、伏笔；对现有 metadata 建适配层和默认值。
- AI 优化章纲→比较→确认，生成正文自动创建/绑定正确文档；章纲与写作右栏共用同一实体。
- 空树、无效绑定、已有文档、并发创建、历史复杂层级全部处理；连续创作范围沿真实顺序计算。

验收：新建卷章→关联人物伏笔→生成或手写→回到大纲仍一致；同章不会因重复点击创建多份文档。

### W06 原生作品设定

- 作品定位：卖点、题材、读者、风格、主题、主线、结局方向、禁区，映射既有 AuthorIntent。
- 人物：列表/搜索/卡片/详情，身份、性格、目标、状态、经历、关系；聚合 Entity/Fact/Relation，不建立第二套人物库。
- 世界观：力量体系、组织、地点、物品、规则等作者分类；保留事实来源、锁定和有效性机制。
- 关系：可先做可编辑关系列表与双向定位，图谱为后续增强，不能只有好看的不可编辑图。
- 时间线：事件顺序、时间、人物、章节来源和修改；伏笔：埋设、推进、回收、关联章与未回收提醒。
- 候选设定变化：差异、影响、来源、接受/拒绝/保留原设定、冲突处理；锁定设定用“固定设定/不可自动修改”等语言表达。

验收：六分区完整 CRUD 与关联；AI 候选不擅改事实；改设定后写作上下文与检查引用更新；普通模式不出现 Canon/Spread/Authority。

### W07 写作台完整功能对等

- 保留现有 textarea 与已验证 AI 主链；本轮不强制换富文本引擎，先把完整能力移进来。
- 章节树补改名、移动、排序、归档/恢复、文档类型兼容；章纲完整字段和人物伏笔可选择、跳转和返回。
- 候选结果提供原文/建议/差异、应用范围、替换/插入/再生成/放弃；生成中与等待确认不掩盖可手工写作能力。
- 历史版本提供来源、时间、标签、预览/比较/恢复；评论与文本锚点、原 Studio 的共同创作与设定变化处理逐项迁入合适抽屉/高级面板。
- 检查报告显示检查版本、问题位置、证据、建议；接受问题、误报、有意保留、生成修改、采纳和重新检查形成闭环。旧报告标为过期，不能显示成当前稿已通过。
- 所有动作说明作用于选区还是整章；未选择文字的整章重写必须清楚表达。模型未配置和额度/网络失败提供可执行入口并保持稿件。

验收：原 Studio 每项能力在迁移矩阵有新位置和用例，不能用“不常用”默认删除；稿件写作主链全程不需要旧 Runs。

### W08 助手、任务中心与连续创作

- 助手：右下角入口/抽屉，自动携带作品、章节、大纲、选区上下文；会话切换、流式回复、引用跳转、停止/失败重试、操作卡片预览确认；上下文切书不能串书。
- 任务：建立后端状态×availableActions×结果类型矩阵，普通语言显示准备、进行、等待确认、暂停、可恢复失败、失败、取消、完成。未知状态给出可诊断提示，不能伪装成功。
- 补齐修订请求、部分结果处理、冲突解决、恢复策略等实际可用动作；任务详情可刷新直达，保留来源文档，结果采纳仍走作者确认。
- 活动/待确认/最近完成分组、角标、分页或按需加载；避免展开前就对每个历史任务高频轮询。高级步骤日志只在详情主动展开。
- 连续创作：在写作页配置起点、结束范围、章数、窗口大小、目标字数、要求、检查与冲突暂停策略；起点/结束章节写入会话并由服务端按真实章节顺序校验，保留旧会话必要高级策略，默认逐章确认，不擅自改变既有作者授权机制。
- 展示每章结果和批次进度，支持暂停/恢复/取消/重试/调整后续要求；离页、刷新、关闭重开后可恢复。同章人工修改时不能被批次静默覆盖。

验收：开始多章任务→离页→刷新→找回批次→处理冲突→采纳→正确章节可见；不跳旧平台，不依赖 React 页面存活维持任务。

### W09 模板、设置与高级能力

- 原生设置覆盖渠道/模型增删改、协议配置、连接测试及阶段结果、创作角色分配、语言、存储驱动、系统备份等现有功能；AI 未配也能使用手工链路。
- 普通设置以“正文创作/检查/策划”等任务角色组织；模型调用、代理技能等保留高级区。密钥遮罩、错误脱敏，导出内容遵循原有敏感配置边界。
- 创作模板整合但不混淆：提示模板、写作风格、写作技能、代理技能与 CreativePreset 各有契约；保留启停、编辑、导入导出、校验及作用范围，项目模板不会误改全局。
- 迁移旧 Delivery 的制作工具：风格提取、技能管理、技能包、导入批次，不让它们在删除旧 Delivery 时丢失。
- 高级工具覆盖旧 Lab 检索、预测、试运行等；清晰显示数据来源与实际执行/预览区别。任务结果回到原生任务中心。
- local/server 两种存储路径都验收；保留历史 OPFS/数据库键、备份格式兼容，必要升级写迁移、失败恢复与回滚说明。

验收：新安装可配置→创建→写作；旧数据可打开与恢复；用户不用切旧设置完成任何既有配置。

### W10 原生交付、导出与备份

- 原生交付页提供章节选择、顺序、质量提示、导出预览、格式、文件命名与结果反馈；当前已支持从大纲选择起止章节，普通导出与文织备份包共享同一范围解析，并把每次预览/下载记录为可追溯导出批次。
- 明确导出使用已保存草稿还是正式版本，并与 UI 预览一致；当前页已显式区分当前正文版本和历史版本，并提示未保存草稿不会进入导出；手工文稿不因 AI 检查缺失被无条件阻塞。
- 作品备份/系统备份区分用途；备份列表、预览、恢复、恢复后定位完整。保护恢复前已有数据，不把恢复失败当成功。
- 对同一作品验证正文、换行、章节顺序、设定、版本及备份支持的数据范围；缺省不包含内容明确列出。
- 保持“导出后手动发布”；B 阶段才增加发布平台、章节、时间、链接和状态记录。

验收：手写→版本→导出→备份→恢复→继续写的完整新平台闭环；下载内容正确，而不只是出现下载按钮。

## 6. 旧平台退出标准

1. 普通导航、按钮、错误重试、空状态、恢复成功、通知、任务引用均进入新产品。
2. 新页面不再 import 并渲染完整旧 Shelf/Bible/Studio/Autopilot/Runs/Lab/Delivery/Settings Workspace；复用下层 hooks/service/纯组件允许。
3. 旧深链保留对象与任务语义，测试前进后退无循环、刷新无误重定向；未知参数安全降级并解释。
4. 普通 UI 无 NarraLume/叙灯旧品牌、Canon/Run/Session/Agent/Skill 等工程术语；法律归属、数据兼容和开发诊断例外。
5. 所有旧功能有迁移状态、目标入口、验收用例；不能通过隐藏按钮、删除路由或删除测试达成“零旧入口”。
6. 完成后按依赖扫描移除无用旧 UI/CSS；保留底层引擎和兼容适配。旧代码保留在 Git 历史，无需给普通用户提供“去旧版完成”退路。

## 7. 测试与验收证据

- 每个工作包列正常、空/加载、失败、刷新恢复、并发、无 AI 状态；相关单元/契约/服务测试先覆盖核心语义。
- 必验端到端：手工开书；AI 三方案；导入；删除恢复；大纲联动；人物锁定与候选变化；手写保存；续写原文保护；选区替换/插入/Diff；检查改稿；版本恢复；助手上下文；连续创作恢复；设置返回；导出与备份恢复；旧深链；数据 CSV 去重。
- 同时覆盖 local 与 server 数据模式。四视口验证主要交互，不把所有桌面功能无说明 skip 掉。
- 人工延迟/断网/503/409、双页面更新、任务生成期间人工编辑、采纳瞬间并发必须有真实断言。
- AI 确定性测试用于验证编排与 UI；真实模型联调单独记录模型环境与结果，不把模拟输出当作真实模型质量证据。不得泄露密钥或凭空声称真实 AI 已验证。
- 不删除旧测试、不降低断言、不扩大 skip 来制造绿灯。实现迁移后可以更新过时 UI 定位，但保留原行为保障。
- 每个里程碑做相关 format/lint/typecheck/test/E2E；阶段收口运行 `npm run verify` 和完整 E2E，记录实际通过/失败/跳过及理由。无新改动不反复跑同一检查。
- 保存主要页面参考对照、四视口截图和失败修复证据到稳定仓库文档/产物目录；`/tmp` 日志不是长期交付物。

体验要求沿用原方案：新用户尽量 3 分钟内开始第一章；主操作清晰；进入作品后最多两次点击回当前章；80% 高频 AI 操作不需写提示词。性能不能仅凭肉眼“流畅”：用大作品样本验证列表/树/正文/任务不会全量高频轮询或明显卡顿，记录样本规模与环境。

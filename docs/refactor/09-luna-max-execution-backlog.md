## 每个切片的固定执行顺序

1. 先读迁移矩阵、当前 gap 和相关契约；列出旧行为与新路径。
2. 先改 domain/contract/persistence/service，再改原生页面；新增迁移必须说明旧库兼容、默认值、回滚和备份影响。
3. 每个动作同时补正常、空态、错误、并发、刷新恢复和无 AI 状态；不以截图或页面存在代替行为证据。
4. 先跑目标 Vitest/API，再跑目标 Playwright 四视口；有 local/server 双模式时各跑一次。
5. 更新 `MIGRATION_MATRIX.md`、`08-current-gap-audit.md` 和本台账，记录真实测试数字和未完成项。
6. 阶段收口必须执行：

   ```bash
   npm run verify
   npm run test:e2e
   git diff --check
   ```

7. 不推送、不部署、不调用第三方发布接口；除非用户另行要求，不创建自动发布或外部平台登录能力。

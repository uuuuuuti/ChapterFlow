# ChapterFlow V1 作者使用说明

这份说明对应 ChapterFlow 新平台的 V1 主链：构思、AI 开书、确认方案、生成大纲与章纲、逐章写作、审阅修订、导出和恢复。

## 1. 启动与安全配置

在仓库 `/Users/armray/Documents/ChapterFlow`：

```bash
npm install
npm run dev
```

打开 Web：`http://127.0.0.1:4318`。服务端 API 为 `http://127.0.0.1:4317`；启动后可访问 `/api/health` 检查数据库和迁移状态。

在服务端的受控、已忽略环境文件中配置：

```dotenv
NARRATIVE_LLM_API_KEY=<你的 DeepSeek API Key>
NARRATIVE_LLM_BASE_URL=https://api.deepseek.com
NARRATIVE_LLM_MODEL=deepseek-v4-flash
NARRATIVE_LLM_CONTEXT_WINDOW=128000
NARRATIVE_LLM_MAX_OUTPUT_TOKENS=8000
NARRATIVE_DATA_DIR=./data-v1
NARRATIVE_BACKUP_DIR=./data-v1/backups
```

不要把 key 放进浏览器 localStorage、代码、提交记录、截图或日志。进入“设置”后确认模型显示为 `deepseek-v4-flash`，执行连接测试；四个阶段都通过后再开始消耗真实模型额度。

## 2. 新建作品与 AI 开书

1. 从“我的作品”点击“新建作品”，或打开 `/books/new?mode=ai`。
2. 输入题材、读者、核心设想和希望兑现的阅读体验。
3. 等待 foundation 候选，比较定位、主线、高潮、终局、人物、世界、事实和伏笔。
4. 只对满意的方案点击“采用/确认”；确认后刷新页面，检查作品设定、大纲和任务中心是否都能读到正式数据。

确认后，平台会把方案保存为可追踪的作品资料，而不是只留在一次对话里。修改锁定事实前先确认它不会掩盖已经写出的正文矛盾。

## 3. 大纲、设定和前 10 章章纲

在“作品设定”检查人物、世界、事实、时间线、伏笔；在“大纲”检查分卷和章节顺序。前 10 章章纲应逐章具备：

- 本章目标与冲突
- 事件、时间、地点和出场人物
- 信息揭示
- 章尾牵引
- 禁改事实
- 目标字数

章纲保存后可以在高级工具中打开并刷新验证。后续生成会消费权威设定、人物当前状态、时间线、未回收伏笔、已确认章纲、前文摘要和必要正文；没有 embedding 时仍会使用必要文本上下文。

## 4. 逐章或批次写作

从“连续创作”进入正常用户入口。V1 建议默认一章一确认：

- 目标字数：2500
- 验收范围：2000—3500 有效字符
- 最大重试：2
- 最大质量修订轮数：2
- 先做一章纵向流程，再授权五章批次

五章批次前先看预算和余额，并明确授权范围。只有明确限定的批次授权可以自动采纳；硬约束冲突或作者新稿存在时必须停在确认边界。平台每章依次执行章纲、上下文、草稿、确定性检查、语义审阅、修订、复检、正式版本、摘要/事实结算和下一章准备。模型截断、占位文本、明显重复或低于 2000 字都不算完成。

在任务中心可以查看 run、步骤、错误和产物。暂停后可刷新页面再恢复；服务重启后重新打开任务中心，先确认 lease/run 状态，再从未完成步骤继续。失败时保留已有候选，不要重复点击造成第二个章节。

## 5. 审阅、修改与版本

审阅报告必须绑定章节和正文版本，并给出具体段落引用、依据、严重度和建议。重点检查：人物知情范围、因果、能力代价、地点/物品/伤势状态、时间线和伏笔回收。

遇到问题时：

1. 先看确定性检查的有效字符数、重复和硬约束结果。
2. 再看语义审阅的证据段落。
3. 采用修订会创建新版本；修订后重新检查最终版本。
4. 不要用修改锁定设定的方式掩盖正文矛盾。
5. 看到 minor/info 也逐项决定是修改、保留还是记入后续章纲。

作者自己编辑后的正文应先保存，再请求检查；平台不会覆盖作者的新稿。

## 6. 导出首发材料

进入“发布”：选择 Markdown 或 TXT，起始章和结束章选定五章范围，版本选择“当前正文版本”。先预览，核对标题顺序和章节数，再下载。下载后可用以下方式核对：

```bash
shasum -a 256 data-v1/exports/雾港第七码头-v1-five-chapters.md
shasum -a 256 data-v1/exports/雾港第七码头-v1-five-chapters.txt
```

平台只记录导出批次，不自动登录或上传第三方站点。作者完成实际上传后，再自行记录平台、范围、日期和链接；未上传时不要创建“已发布”记录。

## 7. 备份与恢复

在发布页填写备份说明，点击“创建备份”。恢复时点击对应快照的“恢复为新作品”，确认后系统创建新作品，不覆盖原作。打开恢复作品的 dashboard、设定、写作和审阅页，确认章节数、版本和报告可读，再把恢复作品作为继续创作的副本。

备份文件保存在 `data-v1/backups/`，不要把其中的数据库或私人稿件提交到仓库。

## 8. 继续第六章

回到作品 dashboard 的“继续写作”，或从“连续创作”选择下一份已保存章纲《第二版印记》。保持目标 2500、范围 2000—3500，并选择逐章确认。生成后先看章纲、正文长度和证据型审阅，再点击“接受正文”；如果需要修改，使用“请求重新修改”。只有作者确认后第六章才会成为正式版本，五章首发导出不会被它悄悄改变。

## 9. 真实模型与故障边界

真实模型门必须始终显示官方 base URL 和精确 model ID。假模型只可用于回归测试，不能用来替代首发验收。若 API key 缺失或额度不足，先保存本地工作和任务上下文，记录为 `blocked` 并补充安全配置；不要降级到 mock 后宣布完成。所有 token、失败、重试和恢复记录都应以任务中心与验收报告为准。

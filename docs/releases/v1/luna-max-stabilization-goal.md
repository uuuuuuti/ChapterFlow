## 二、先修可靠性不变量，再花真实模型额度

### A. 唯一章节顺序和批次范围

- 按祖先与 sibling ordinal 定义权威目录顺序，所有目录显示、上下文、前后章、审阅、批次、导出共用；不得按含 UUID 的 path 字典序当章序。
- 覆盖跨篇重排、随机 ID、单篇超过十章、删除范围端点。无效范围必须明确报错，不静默扩大。
- 验收固定全书第 1—5 章；续写固定全书第 6 章。批次第几章与全书第几章分别标识，不挑其他已通过正文替代。
- 连续写作只在明确授权的章节范围与数量内运行；耗尽范围不能偷偷重规划并扩出新章。

### B. 当前版本审阅与结算闭环

- 所有作者保存、AI 采纳、修订采纳路径统一处理版本变化，不依赖 source 文本恰好等于 manual。
- 审阅、确定性检查、摘要、事实、人物状态、时间线及联合报告绑定正文版本/hash；改变正文后旧结果显式 stale，不当成当前 pass。
- 当前正文不能配旧摘要；无 embedding 仍能读取必要文本和正确结算。上章结算失败要保留成果并恢复，不能跳过去生成下一章或把批次记完成。
- 幂等结算，不重复累加事实；修订导致事实变化有可追踪替代/撤回，不改锁定设定掩盖正文矛盾。
- 作者有新稿时不得覆盖；并发保存、采纳、恢复须保护 currentVersion 基线。

### C. 真正执行质量门

- 同一个最终内容 hash 必须同时通过确定性与语义门，不允许最后一个 semantic pass 掩盖字数、截断、占位、重复或硬约束失败。
- 不合格候选可保存供作者处理，但不得自动结算成合格正文、累计完成章数或继续下一章。critical 及 V1 阻断类 major 未解决时停下；不得以 revise 无 critical 为由自动过门。
- 默认目标 2500 字；每章验收 2000—3500，前五章总计至少 10000。抽取可计正文的统一纯函数供 worker、编辑器、质量页、导出、验收使用；排除标题、标记、空白、思考，不把截断、占位、明显重复或灌水当完成。
- 保留作者确认机制，只有可见且明确限定的批次授权允许自动采纳；硬约束冲突不能被批次授权越过。
- 审阅给章节/版本/引用/依据/严重度。用有界覆盖机制检查人物知情、时间线、因果、能力代价、物品/地点/伤势、伏笔；不能拿“最多三个问题”的一次返回证明全范围无阻断。
- 修订后复检最终版本；前五章做绑定准确五个最终 hash 的联合审阅，阻断为 0，warning 逐项列出处理决定。任何相关版本变化使联合结论失效。

### D. 预算与失败恢复

- 官方 URL 固定 `https://api.deepseek.com`，精确模型固定 `deepseek-v4-flash`。复用兼容适配器，依据官方文档与真实响应验证 JSON、SSE、推理/正文隔离、工具回合、finish reason 与 token 预算，不只改 UI 标签；不得静默降级到 mock 或其他模型。
- 开书、规划、写作、审稿、修订、结算各岗位保存脱敏的实际解析及调用证据。未配置费率显示金额未知，不显示免费；分别记录 input/output/cache（若提供）、调用数、失败重试、累计调用耗时与实际墙钟耗时。
- 实际调用前公布并保存此次验收总预算与五章批次 calls/input/output/time 有限上限；有可信费率时加金额上限。后台必须执行会话级预算，跨重试、子 run、暂停/重启仍累计，失败重开不能刷新预算。瞬态重试至多 2 次、每章质量修订至多 2 轮，超限保留成果并等待作者处理，不自行加预算。
- 没 Key 时先完成所有可独立实现和测试，再给准确安全配置步骤；真实模型门标 blocked，不宣布完成、不重复空转。只使用服务端安全配置或已忽略环境文件，不输出、复制或提交用户密钥；若官方拒绝指定模型，记录真实错误并请求决定，不改模型验收。
- 对 run 创建/关联、正式版本提交、结算、章数记账等边界做故障注入，验证事务或等效幂等恢复；刷新、重复点击、网络响应丢失、暂停和服务重启不重复章节、不丢结算、不遗留活跃孤儿任务。

## 三、修好普通作者入口与重复交互

- 开书确认后正式保存定位、主线/高潮/终局、分卷规划、人物/世界/事实/伏笔、十份章纲；章纲包含目标、冲突、事件、时间地点、人物、信息揭示、章尾牵引、禁改事实和字数目标。普通作者流程可生成、编辑、确认、刷新继续，不依赖代理在高级工具手工补齐必需数据。
- 全书规划不能被当前窗口 rolling outline 代替。用 context receipt 证明后续写作消费确认规划和设定；未来规划与已经发生/人物已经知道的事实分开。
- 滚动规划明确“续接现有篇章”还是“创建新篇章”，身份使用稳定 ID，不按标题粗暴去重。保留不同内容的同名篇章时提供可理解名称和层级。
- 恢复副本标记来源、恢复时间、用途，允许打开已有恢复结果或明确再建副本。同一次恢复意图在未知结果重试时复用幂等键；故意再次恢复可用新意图。
- 作品库区分正式作品、恢复/验收副本及归档；避免最近创作和全部作品无区分地占满重复卡片，统计口径明确。
- 现有两份恢复副本、两个同名 arc、两份不同 hash 备份不可直接删除/合并。先列确切目标与用户后续修改，必要时请求用户确认；默认保留。新的验收数据隔离并清晰标识，恢复验证后不污染作者活跃作品。
- 发布页分开“全书提醒”和“所选首发范围验收”；展示当前版本阻断与警告、具体原因、修复回链。计划章不因打开空编辑器就突然成为首发阻断。历史审阅与当前待办分开。
- 区分预览、下载、实际发布：避免不可理解的同名批次堆积；允许草稿导出但明确未通过验收。未上传第三方不得记已刊登。
- 作品备份与系统数据库备份明确区分；中文 sizeBytes 用实际 UTF-8 字节数。提供可携作品包和 manifest，不只证明 DB 中存在快照。
- 1440/1024 桌面检查开书、章纲、设定、写作、审阅、任务、发布主链。主要操作可找到，加载/禁用/失败状态明确，保存与离开不丢稿；折叠、弹窗、键盘焦点正确。普通操作和所有任务/错误回链留在新平台。

## 四、验证路径：先一章，再五章，不靠代理补洞冒充产品

1. 每个修复先运行相关检查，覆盖上述顺序、版本、质量、预算、幂等不变量。mock 只用于故障回归，与真实模型证据明确隔离。
2. 验证干净构建产物下作者启动步骤可用，解决 src/dist 陈旧依赖问题；不重置用户工作树。记录最终构建标识、配置与数据位置。
3. 修复稳定后，从浏览器新建一个明确标记的 V1 验收作品。先验证真正第一章的纵向闭环，再扩展至前五章；一个批次的 first chapter 不得偷换成全书第一章。
4. 全程使用普通页面入口和正常服务端 worker；可浏览器自动化，但不直接写数据库造稿，不用脚本调用 advance 冒充后台 worker，不用代理线下手写正文或隐蔽 API 操作补流程缺口。允许作者正常编辑，但必须经产品保存、复检、结算，注明操作。
5. 真实链路包含刷新、暂停/恢复、服务重启恢复，保留任务和产物证据；危险故障先在隔离测试验证。停止正在使用的作者服务前确认没有冲突，优先隔离验收实例。
6. 导出全书第 1—5 章最终版本 TXT/Markdown、首发书名/简介/标签/目录、可携备份包；实际读文件核对顺序、内容、有效字数和 hash。正文/数据库置于本地受控且忽略目录，不意外提交私稿或密钥。
7. 通过用户入口恢复包，核对正文、版本、审阅引用、设定、章纲、结算及必要历史的语义等价。恢复历史不得冒充本次真实运行或重复计算用量。
8. 重新进入作品，基于当前前五章状态生成全书第 6 章候选；保存可恢复，保留作者最终采纳边界，不自动发布。
9. 最终运行项目规定的完整检查（至少根 npm run verify）以及相关 browser E2E、恢复回归、V1 真实浏览器链路。不能拿旧 smoke/旧平台测试替代，不为凑测试数扩到 V2；有失败就定位修复，最终结果必须对应最终构建。

## 五、证据与停止条件

在 `docs/releases/v1/` 维护简洁清单、当前报告和作者说明，状态仅 pending/doing/blocked/passed。每个 passed 有可复核真实证据，缺证据不能沿用旧 passed。

G0—G6 全部重新满足，真正前五章交付和第六章续写证据齐全，最终检查通过，才可标 Goal complete。缺凭据、预算耗尽或需要新的用户授权时保留成果，如实说明阻塞，不谎报完成、不无界重试。不要用反复全套测试或重复“仍在检查”替代推进。
